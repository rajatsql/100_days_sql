## 🧠 Problem-Solving Approach

For every problem, I follow a structured thought process:

```
Understand the requirement
          ↓
Identify the required output
          ↓
Identify tables and columns
          ↓
Understand table relationships
          ↓
Identify filtering conditions
          ↓
Check whether aggregation is required
          ↓
Choose JOIN / Subquery / CTE
          ↓
Check whether Window Functions are useful
          ↓
Write the query
          ↓
Test the result
          ↓
Check edge cases
          ↓
Review the query
          ↓
Optimize if required
```

The goal is to learn how to think about a SQL problem, not memorize a specific query.

## 🧩 Key SQL Patterns

The challenge focuses heavily on reusable SQL patterns:

**GROUP BY + HAVING** — Used for filtering aggregated results.
```
GROUP BY → Aggregate → HAVING
```

**JOIN + Filtering** — Understanding the difference between `JOIN ... ON ...` and `WHERE ...`

**Aggregation Before JOIN**
```
Raw Data → Aggregate → JOIN → Final Result
```

**Latest Record**
```
ROW_NUMBER() + PARTITION BY + ORDER BY DESC
```

**Ranking**
```
RANK() / DENSE_RANK() / ROW_NUMBER()
```

**Missing Records**
```
NOT EXISTS
or
LEFT JOIN WHERE right_table.id IS NULL
```

**Previous / Next Record**
```
LAG() / LEAD()
```

**Complex Logic**
```
CTE → JOIN → Aggregation → Window Function → Final Result
```
